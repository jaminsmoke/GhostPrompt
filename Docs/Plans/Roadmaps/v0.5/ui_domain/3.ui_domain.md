# Roadmap v0.5.3 — Mover `webview/` + `vscode/` → `src/ui/` con subdominios

> Estado general: 🔵 Planificado → ⚪ No iniciado | 🟡 En progreso | 🟢 Completado | 🔴 Bloqueado

---

## Contexto

Tras las reorganizaciones de `host/` → `api/` + `vscode/` + `core/pipeline/` y `projectMemory/` → `core/memory/`, quedan dos dominios top-level fuera de lugar:

1. **`webview/` en la raíz del repo** — el único código fuente fuera de `src/`. Debería estar dentro de `src/ui/webview/`.
2. **`vscode/`** — es UI (providers, HTML, notifications), no un dominio separado. Debería vivir bajo `ui/provider/` y `ui/notifications/`.

### Problema

- `webview/` fuera de `src/` rompe la coherencia del proyecto (todo el código fuente debería estar bajo `src/`)
- `vscode/` tiene un nombre confuso: sugiere "integración VS Code genérica" pero solo contiene UI del webview
- 3 archivos en `vscode/` que son claramente UI: providers, HTML generation, notifications

### Solución

Crear el dominio canónico `src/ui/` con subniveles que reflejen dónde corre cada pieza:

- **`ui/webview/`** — Corre en el webview sandbox (navegador). Contiene `index.html`, `style.css`, `main.ts`, `lib/`, `protocol/`, `panels/`.
- **`ui/provider/`** — Corre en Node (extension host). Contiene `MiniInputViewProvider.ts`, `webviewHtml.ts`.
- **`ui/notifications/`** — Corre en Node. Contiene `suggestionNotification.ts`.
