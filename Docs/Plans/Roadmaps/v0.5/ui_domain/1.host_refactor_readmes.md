## Contexto

Tras la reorganización v0.5.2 (`core/` + `system/`), la carpeta `host/` (10 archivos) sigue mezclando 4 responsabilidades distintas bajo un nombre que no describe ninguna:

1. **API interna webview↔host** — protocolos Zod, handlers inbound, settings postMessage, apply update, workspace getters (6 archivos)
2. **Integración VS Code** — `WebviewViewProvider`, HTML/CSP generation, notifications (3 archivos)
3. **Config getters** — lectores de `vscode.workspace.getConfiguration` (1 archivo, parte de API)
4. **Pipeline de suggestion** — orquestación governor → LM → broadcast (2 archivos, lógica pura de core)

### Problema

- `host/` no comunica qué hace: ¿es un provider? ¿un handler? ¿una API?
- El pipeline de suggestion (lógica pura) vive junto a HTML generation (integración VS Code)
- Los contratos Zod y handlers están al mismo nivel que `MiniInputViewProvider`
- No hay READMEs en ninguna carpeta canónica explicando su rol, contratos y expectativas

### Solución

Tres movimientos + documentación:

- **`api/`** — API interna: protocolos, handlers, settings, getters
- **`vscode/`** — Integración VS Code: providers, HTML/CSP, notifications
- **`core/pipeline/`** — Orquestación de suggestion (lógica pura)
- **READMEs** en cada dominio canónico
