# Roadmap v0.3.0d — OpenCode: streaming, selector y catálogo

> **Línea de versión:** sigue siendo **GhostPrompt 0.3.0** (sin salto a 0.4.0 hasta decisión de release global).
>
> **Antecedentes:** oleada **v0.3.0c** ([`Roadmap-v0.3.0c-opencode-ux-perf.md`](./Roadmap-v0.3.0c-opencode-ux-perf.md)) cerrada; spike SDK ([`Spike-v0.3.0c-opencode-sdk-upstream.md`](../Spikes/Spike-v0.3.0c-opencode-sdk-upstream.md)) con hallazgos de SSE probados en runtime.

---

## Objetivo

1. **Ghost-text progresivo (OpenCode):** aprovechar eventos SSE **`message.part.delta`** para mostrar la sugerencia **antes** de que termine `session.prompt`, con reglas claras de **qué parte** del mensaje se muestra (respuesta final vs razonamiento interno).
2. **Selector de modelos unificado:** acercar la UX del dropdown OpenCode a la de Copilot: etiquetas **claras para modelos gratuitos** (p. ej. **Gratis**, alineado con “included” / cuota segura) y distinción de pago cuando aplique.
3. **Catálogo completo y esperado:** cerrar brechas entre lo que el usuario configura en OpenCode y lo que GhostPrompt lista (p. ej. modelos **free** que no aparecen — revisión **Phi‑3** / nombres tipo **hy**).

---

## Hallazgos que motivan este roadmap

| Hallazgo                                                                               | Implicación                                                                                                                                            |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SSE **`message.part.delta`** con `delta` en fragmentos                                 | Streaming incremental viable para la UI.                                                                                                               |
| Primera parte frecuente: **`type: reasoning`**                                         | Hay que **filtrar por parte** (o por `partID` tras `message.part.updated`) para no volcar razonamiento interno en el ghost-text.                       |
| **`/event`** y **`/global/event`** redundantes                                         | Una sola suscripción SSE en implementación productiva (menos carga y menos logs).                                                                      |
| Hoy OpenCode en catálogo usa **`tier: "unknown"`** siempre (`opencodeModelCatalog.ts`) | La UI muestra `[UNKNOWN]` como Copilot muestra `[INCLUDED]`/`[PREMIUM]` — hay que enriquecer **tier/pricing** desde metadatos OpenCode cuando existan. |

---

## Fase A — Streaming de sugerencia (OpenCode)

**Meta:** Ghost-text que se **rellena en vivo** mientras el modelo genera, sin perder `session.prompt` como cierre consistente (normalización, límites de caracteres, cancelación).

**Estado:** **Cerrada** en código (2026-05-09). `consumeOpencodeSuggestionTextStream` (`opencodeSuggestionStream.ts`); mensaje `suggestion-stream`; filtro `sessionID` + partes `type === "text"`; tests `opencodeSuggestionStream.test.ts`.

| ID     | Tarea                   | Notas                                                                                                          |
| ------ | ----------------------- | -------------------------------------------------------------------------------------------------------------- |
| **A1** | Suscripción SSE única   | [x] Solo `client.event.subscribe` (`GET /event`).                                                              |
| **A2** | Filtro de partes        | [x] Deltas solo si `partKinds.get(partID) === "text"` (excluye `reasoning`).                                   |
| **A3** | Contrato host → webview | [x] `suggestion-stream` + `text` acumulado; `suggestion` final sin cambios de contrato base.                   |
| **A4** | Cancelación y carreras  | [x] `sseAbort` ligado a token; preview solo si `captureId === activeCaptureId`; filtro por `sessionId` en SSE. |
| **A5** | Tests / opt-in          | [x] Tests unitarios de fold/unwrap; integración live sin cambio de política opt-in.                            |

**Criterio de salida:** Con OpenCode, el usuario ve **actividad de generación** antes del texto final, sin mostrar (por defecto) el bloque de razonamiento completo en inglés.

## Fase B — Selector OpenCode: “Gratis” y paridad con Copilot

**Meta:** En el desplegable, los modelos **sin coste o de capa gratuita** se identifican de forma **tan clara** como en la rama Copilot (included), no genérico `[UNKNOWN]`.

**Estado:** **Cerrada** en código (2026-05-09). `classifyOpencodeModelTier` (`opencodeModelTier.ts`); catálogo + `resolveOpencodeModelIds` respetan **`nonPremiumOnly`**; webview **`formatTierToken`** con ES/EN; README párrafo _OpenCode model tiers_.

| ID     | Tarea                       | Notas                                                                                                                                 |
| ------ | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| **B1** | Mapeo tier desde API        | [x] `pricing` tipo `0x`/`1x`, flag `free` cuando exista en el objeto modelo.                                                          |
| **B2** | Heurística controlada       | [x] Proveedor `opencode`, backends tipo **ollama**/local, marcadores **premium** en nombre/id, rutas `:free`; documentado en README.  |
| **B3** | Webview / i18n              | [x] ES: **`[Gratis]`**, `[Premium]`, `[Sin clasificar]`; EN: `INCLUDED`/`PREMIUM`/`UNKNOWN`; usa `effectiveSuggestionLanguage`.       |
| **B4** | `nonPremiumOnly` y OpenCode | [x] Oculta modelos **premium** en el listado; **Auto** elige el primer modelo no premium; id explícito premium → `no-included-model`. |

**Criterio de salida:** Un usuario en **español** ve **Gratis** (o etiqueta equivalente clara) en filas OpenCode free, y no mezcla visual “unknown” con modelos claramente gratuitos.

## Fase C — Catálogo: modelos que faltan (p. ej. Phi‑3 / “hy3”)

**Meta:** Alinear expectativas con **OpenCode CLI + proveedores**; reducir “no veo el modelo X”.

| ID     | Tarea                         | Notas                                                                                                                                                                           |
| ------ | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **C1** | Repro local                   | `opencode` + `config.providers` en el mismo entorno que GhostPrompt; anotar ids `providerID/modelID`.                                                                           |
| **C2** | **Phi‑3** / nombres similares | Comprobar si el modelo deseado es **Phi‑3** (p. ej. vía proveedor local o remoto) o otra variante; corregir documentación o registro en OpenCode, no asumir bug en GhostPrompt. |
| **C3** | Trazas de depuración          | Con `ghostPrompt.debugSuggestions`, loguear recuento e ids del catálogo al fusionar listas.                                                                                     |
| **C4** | Documentación                 | README: _Requisitos OpenCode_ — modelos visibles = los que **OpenCode** expone; enlace a config de proveedores.                                                                 |

**Criterio de salida:** Lista de comprobación publicada (o en README) para “modelo no aparece”: OpenCode config, exclusión en `opencodeExcludedModelIds`, y versión de CLI.

---

## Fuera de alcance (v0.3.0d explícito)

- Sustituir **completamente** `session.prompt` por solo SSE (el cierre seguirá validando el sobre normalizado).
- Garantía de paridad de **precios** con el portal de cada proveedor (solo lo que la API o heurística permita).
- Bump de versión de marketplace **0.4.0**.
